# NSUK-1.21.1 开发者教程：添加模组矿物与群系适配

本文面向需要为 NSUK-1.21.1 添加矿脉定义、接入其他模组物品或适配模组群系的开发者。

本文中的“矿物”指 NSUK 的虚拟矿脉，不是直接向世界生成方块矿石。虚拟矿脉的储量、产量和状态保存在 SQLite 存档数据中，并由矿物钻井平台和地质锤查询。

## 1. 先了解数据流

一次矿脉查询大致经过以下步骤：

```text
data/<namespace>/virtual_veins/*.json
        |
        v
VirtualVeinDefinitionLoader（数据包重载时加载和校验）
        |
        v
VirtualVeinService（按种子、256 格矿区单元和群系 ID 建立矿区键）
        |
        v
六项气候参数匹配 -> 按 priority 选最多两个候选矿脉
        |
        v
SQLite 保存矿区档案，内存缓存只保存当前运行时副本
```

因此：

- JSON 只声明矿脉定义，不直接生成方块。
- 同一个矿区最多选择两个矿脉定义。
- 候选按 `priority` 降序排序；优先级相同时按 `id` 的字典序排序。
- 一个已经写入 SQLite 的矿区不会因为新增 JSON 自动重新抽取矿脉。
- `/reload` 会重新加载定义并清空内存缓存，但不会删除已有矿区档案。测试新矿脉时请使用新世界，或使用项目已有的存档数据清理流程。

## 2. 添加一个模组物品作为矿脉产物

矿脉 JSON 的 `product` 必须是已经注册到物品注册表的完整资源 ID。先在物品注册类中注册物品，例如：

```java
public static final DeferredHolder<Item, Item> RAW_CHROMITE = ITEMS.register(
        "raw_chromite", () -> new Item(new Item.Properties()));
```

物品资源 ID 是：

```text
my_mod:raw_chromite
```

还需要在客户端语言文件中提供名称：

```json
{
  "item.my_mod.raw_chromite": "Raw Chromite"
}
```

`VirtualVeinDefinitionLoader` 加载 JSON 时会调用 `BuiltInRegistries.ITEM.containsKey(productId)`。如果物品没有注册、资源 ID 拼错，整份矿脉定义会被拒绝并写入错误日志。

## 3. 创建矿脉 JSON

文件放在数据包的以下路径：

```text
src/main/resources/data/my_mod/virtual_veins/chromite_vein.json
```

当前解析器要求以下字段全部存在：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 矿脉内部 ID，必须非空。建议使用 `my_mod:chromite_vein`，避免与其他模组冲突。 |
| `display_name` | 字符串 | 地质锤和钻井界面显示的矿脉名称。当前是直接文本，不是翻译键。 |
| `priority` | 整数 | 候选排序优先级，数值越大越容易进入前两个候选。 |
| `conditions` | 对象 | 六项原版多重噪声气候参数范围。每项必须是两个数字组成的闭区间。 |
| `y_range` | `[整数, 整数]` | 世界 Y 高度范围，当前必须处于 `-64` 到 `320`。 |
| `product` | 资源 ID | 产物物品，例如 `my_mod:raw_chromite`。 |
| `production` | 对象 | `min_amount`、`max_amount` 和 `period_ticks`。 |

一个完整示例：

```json
{
  "id": "my_mod:chromite_vein",
  "display_name": "铬铁矿脉",
  "priority": 45,
  "conditions": {
    "continentalness": [0.10, 0.85],
    "erosion": [-0.70, 0.20],
    "depth": [0.00, 1.00],
    "temperature": [-0.40, 0.40],
    "humidity": [-0.80, 0.20],
    "weirdness": [0.20, 0.90]
  },
  "y_range": [-48, 8],
  "product": "my_mod:raw_chromite",
  "production": {
    "min_amount": 2,
    "max_amount": 6,
    "period_ticks": 2400
  }
}
```

### 3.1 `conditions` 的六个参数

这些参数来自 Minecraft 1.21.1 的原版多重噪声气候系统，值通常在 `-1.0` 到 `1.0` 之间。`depth` 是气候噪声的深度参数，不是方块 Y 高度；方块高度只由 `y_range` 控制。

| 参数 | 含义 |
| --- | --- |
| `continentalness` | 大陆性，从海洋到内陆 |
| `erosion` | 侵蚀程度，影响地形起伏和地貌 |
| `depth` | 多重噪声地形深度，不等同于地下深度 |
| `temperature` | 温度 |
| `humidity` | 湿度 |
| `weirdness` | 奇异度，影响变种地貌 |

匹配不是“精确等于某个值”，而是定义范围与当前原版参数点有交集即可。范围越宽，矿脉候选越多；范围过宽会让不同矿脉大量竞争前两个名额。

建议调试顺序：

1. 先让六项范围都使用较宽范围，确认 JSON、物品 ID 和产量都能工作。
2. 再一次只收窄一个参数，并在新世界中检查候选是否符合预期。
3. 最后调整 `priority`，解决同一气候区域内多个矿脉的竞争关系。

### 3.2 Y 高度和产量

- `y_range` 是闭区间，例如 `[-48, 8]` 包含 Y=-48 和 Y=8。
- `min_amount` 必须大于 0，且不能大于 `max_amount`。
- `period_ticks` 必须大于 0。Minecraft 每秒 20 tick，因此 `2400` tick 约等于 120 秒。
- 钻井平台在当前 Y 位置选择矿脉；地质锤探查点击位置向下 60 格的 Y 范围。

## 4. 添加或适配模组群系

当前矿脉系统没有读取下面这种字段：

```json
"biomes": ["my_mod:volcanic_wastes"]
```

直接添加该字段不会产生任何效果。系统的群系处理方式是：

1. 从世界生成器的 `BiomeSource` 获取当前位置的群系 ID。
2. 使用种子、256 格矿区单元坐标和群系 ID 生成 `VirtualVeinFieldKey`。
3. 在海平面采样当前位置的气候参数。
4. 从当前世界 `MultiNoiseBiomeSource` 的运行时参数表中，寻找该群系自己的可用参数点。
5. 用矿脉 JSON 的六项 `conditions` 与该参数点匹配。

### 4.1 普通模组群系

如果模组群系已经正确注册到 `Registries.BIOME`，并且被 TerraBlender 等合并进当前世界的 `MultiNoiseBiomeSource`，NSUK 会用它的群系 ID 分区，并用它自己的六项参数点选矿种。为该群系设计矿脉时，应使用该群系实际的气候参数来写 `conditions`，而不是只写群系名称。

原版洞穴和深暗之域仍被排除。只有当前群系在世界参数表里没有任何可用点时，才会在同一张表里回退到最近的可用点；不会再换成原版 Overworld 预设。已建档的矿区不会因这次规则更新而重抽。

### 4.2 需要严格群系白名单时

如果需求是“矿脉只能出现在 `my_mod:volcanic_wastes`，不允许气候相近的其他群系出现”，需要扩展代码，而不是继续堆 JSON 字段：

1. 在 `VirtualVeinDefinition` 中增加可选的群系 ID 集合。
2. 在 `VirtualVeinDefinitionLoader` 中解析并校验 `biomes` 数组。
3. 在 `VirtualVeinService.selectCandidates` 或生成档案前，将当前位置的 `biomeId` 传入匹配逻辑。
4. 保留六项气候参数作为第二层筛选，避免自定义群系的地形参数点缺失时产生误匹配。
5. 为严格白名单添加单元测试，覆盖允许群系、拒绝群系和空数组三种情况。

不要仅通过客户端显示名或地质锤提示判断群系；矿区键和候选筛选必须在服务端完成。

## 5. 重载与验证流程

### 数据包重载

开发环境中可以执行：

```text
/reload
```

成功时日志会出现类似：

```text
Loaded N virtual vein definitions
```

无效文件不会让整个服务器崩溃，但该文件会被跳过并记录错误。重点检查：

- `product` 是否已经注册。
- 六个 `conditions` 是否每项恰好两个数字。
- `y_range` 是否在 `-64..320` 内且最小值不大于最大值。
- `production` 的数量和周期是否为正数。

### 测试

至少运行矿脉定义和气候匹配测试：

```powershell
.\gradlew.bat test --tests common.cn.kafei.simukraft.virtualvein.VirtualVeinDefaultDefinitionsTest
.\gradlew.bat test --tests common.cn.kafei.simukraft.virtualvein.VirtualVeinFieldResolverTest
```

建议为每个新增矿脉补充以下检查：

- JSON 能被 `VirtualVeinDefinitionLoader.parse` 解析。
- `product` 在注册表中存在。
- 六项条件至少能匹配目标群系在世界参数表中的气候点。
- Y 范围和生产周期满足构造器约束。
- 同一矿区最多仍只有两个候选矿脉。

## 6. 常见问题

### `/reload` 后仍然没有新矿脉

已有矿区档案保存在 SQLite 中，重载只清除内存缓存，不会重抽已有矿区。请换一个未生成过档案的矿区，或在开发存档中清理对应数据后再测试。

### 日志提示 `Unknown item`

物品注册名、命名空间或资源路径写错了。确认物品注册发生在注册事件中，并使用完整 ID，例如 `my_mod:raw_chromite`。

### JSON 加了 `biomes` 但没有效果

当前格式不支持显式群系数组。请根据群系的多重噪声气候参数配置六项 `conditions`；如果必须严格限制群系，需要按第 4.2 节扩展 Java 模型、加载器和服务匹配逻辑。

### 矿脉数量总是不超过两个

这是 `VirtualVeinService` 的设计上限，不是 JSON 解析失败。提高优先级只能改变入选顺序，不能把上限提高到三个或更多。

## 7. 发布前检查清单

- [ ] 物品已注册，并且有中英文名称。
- [ ] JSON 位于 `data/<namespace>/virtual_veins/`。
- [ ] `id` 全局唯一，`display_name` 可读。
- [ ] 六项气候条件均为合法二元范围。
- [ ] `y_range` 位于 `-64..320`。
- [ ] 产物 ID 存在，数量和周期为正数。
- [ ] 新世界和已有矿区都分别验证过行为。
- [ ] `VirtualVeinDefaultDefinitionsTest` 与 `VirtualVeinFieldResolverTest` 通过。
- [ ] 如果使用自定义群系，已确认其 `BiomeSource` 能返回正确群系 ID。
