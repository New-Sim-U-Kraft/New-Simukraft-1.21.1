# 城市升级系统

本文档描述 New:Sim-U-Kraft 在 Minecraft 1.21.1 NeoForge 中的城市等级数据包、服务端升级任务和城市核心界面行为。

## 基本规则

- 服务端是唯一权威端。客户端只显示城市核心快照并发送升级请求。
- 升级条件、升级完成后解锁的容量和升级耗时都由数据包定义。
- 资源在任务开始时扣除；城市等级和解锁容量在任务结束时生效。
- 进行中的任务保存到 `CityData` NBT，并由现有 SQLite 城市存储链路持久化；不新增数据库表。
- 计时使用 `ServerLevel#getGameTime()`，停服不消耗时间，重启后继续。

## 数据包位置

```text
data/<namespace>/city_levels/<file>.json
```

内置配置文件：

```text
src/main/resources/data/simukraft/city_levels/city_levels.json
```

根节点可以是单个等级对象、等级数组，或推荐使用的 `levels` 数组包装对象。

## 等级定义

```json
{
  "level": 4,
  "display_name": "城镇",
  "duration_ticks": 800,
  "requirements": {
    "funds": 10.0,
    "population": 5,
    "items": [
      {
        "tag": "minecraft:logs",
        "count": 16,
        "display_icon": "minecraft:oak_log",
        "display_name": "原木"
      },
      {"item": "minecraft:cobblestone", "count": 16}
    ]
  },
  "unlocks": {
    "chunks": 49,
    "enclaves": 3
  }
}
```

### 根字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `level` | 整数 | 必填。最小为 1；只能升级到当前等级的连续下一级。 |
| `display_name` | 文本 | 可选。等级名称，缺省为 `Lv<level>`。 |
| `duration_ticks` | 整数 | 可选。升级耗时，Lv1 缺省为 0，其他等级缺省为 1200，最大为 1728000。Lv2 及以上必须大于 0。 |
| `requirements` | 对象 | 可选。发起升级时需要满足的资金、人口与物品。 |
| `unlocks` | 对象 | 可选。升级完成后生效的区块和飞地容量。 |

### 升级条件

- `requirements.funds`：非负资金，服务端按两位小数校验。
- `requirements.population`：非负人口。
- `requirements.items`：最多 64 条，每条 `count` 在 1 到 1000000 之间。
- 每条物品条件必须且只能设置 `item` 或 `tag`。`item` 兼容 `#minecraft:logs` 标签写法。
- 标签条件按物品标签匹配和扣除；展示字段不改变服务端的材料校验。
- 相同物品或标签条件会合并数量。重复条件中若同时给出互相冲突的展示图标或名称，等级定义会被拒绝。

### 材料展示字段

物品条件可选设置以下字段，仅影响城市核心材料列表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `display_icon` | 物品 ID | 可选。使用该物品作为图标，例如 `minecraft:oak_log`。必须是已注册物品。 |
| `display_name` | 文本 | 可选。直接显示的材料名称，最大 128 个字符。不是翻译键。 |

两个字段省略时，精确物品保留原本地化名称和原图标。标签没有固定代表物品，会保留原有标签标识和默认图标；因此 `minecraft:logs` 使用橡木原木图标和“原木”作为展示代表，但仍接受所有属于该标签的原木。

### 升级后解锁

- `unlocks.chunks`：升级完成后的城市区块容量。`-1` 表示无限制，最大有限值为 1000000。
- `unlocks.enclaves`：升级完成后的飞地容量。`-1` 表示无限制，最大有限值为 15。
- 解锁字段不是升级条件。升级完成前仍使用当前城市等级的容量。

当前内置等级从 Lv1 到 Lv12；Lv2 至 Lv12 的耗时为 400 到 2400 tick，约 20 到 120 秒。飞地从 Lv2 开始提供，Lv11 达到 15 块。

## 建筑等级解锁

建筑是否需要达到指定城市等级，由建筑包中的 `.sk` 元数据单独声明，不写入城市等级 JSON 的 `requirements` 或 `unlocks`：

```text
name:大房子B
size:15 x 11 x 15
amount:10.60元
author:XiaoLiang小亮 MioPha
description:大房子系列里最舒适温馨的房子
tags:price_low,material_low,stage_early
unlockLevel:4
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `unlockLevel` | 正整数 | 可选。城市达到该等级后才可选择和开始建造；例如 `4` 表示 Lv4 解锁。 |
| `unlock_level` | 正整数 | `unlockLevel` 的兼容写法，仅在未声明 `unlockLevel` 时读取。 |

- 字段缺失、空白或只有冒号而没有值时，建筑无等级限制。
- 指定后必须是大于 0 的整数；零、负数或非数字会使建筑元数据无效。
- 城市等级达到或高于解锁等级即可使用，升级任务进行中仍按升级前的城市等级判断。
- 建筑列表根据服务端下发的城市等级显示锁定状态；真正开始施工时，`BuildBoxStartConstructionPacket` 会在服务端重新读取 `.sk` 并校验城市等级，不能通过客户端预览或伪造请求绕过。
- 该字段只控制建筑可用性，不会自动增加区块、飞地、人口或住房容量；容量仍由城市等级 JSON 的 `unlocks` 定义。

## 服务端升级流程

```text
CityUpgradePanelFactory
  -> CityUpgradeRequestPacket
  -> CityUpgradeService.upgrade
  -> 扣除资金和材料，写入 CityUpgradeState
  -> CityManager.persistUpgrade
  -> CityUpgradeService.tick
  -> CityData.completeUpgrade
  -> 持久化等级、发送城市消息、同步 HUD
```

开始任务前，服务端会校验玩家权限、客户端等级快照、连续的下一等级定义、SQLite 可用性、城市资金、实时人口和玩家背包材料。只有官员及以上权限可以发起升级。

校验成功后，服务端立即扣除资金和材料并写入财政流水，但城市等级保持不变。正在升级的城市会拒绝新升级请求。

每个服务端 tick 都会检查进行中的任务。满足以下条件后，才提高城市等级并清空任务：

```text
level.getGameTime() >= startedAt + durationTicks
```

完成持久化失败时，服务端恢复原等级和升级任务状态，避免出现已解锁但未保存的状态。

## 持久化状态

进行中的任务写入 `CityData`：

| NBT 字段 | 含义 |
| --- | --- |
| `UpgradeTargetLevel` | 目标等级 |
| `UpgradeStartedAt` | 服务端世界起始游戏 tick |
| `UpgradeDurationTicks` | 本次升级总耗时 |

旧存档没有这些字段时按无任务加载。损坏或与当前等级不连续的任务状态会被忽略，防止跳级。

## 网络接口

### C2S：升级请求

`CityUpgradeRequestPacket`，网络 ID 为 `simukraft:city_upgrade_request`：

```text
pos                  BlockPos
expectedCurrentLevel VarInt
targetLevel          VarInt
```

服务端不会信任客户端的资金、人口、材料数量或耗时，全部重新读取服务端状态。

### S2C：城市核心快照

`CityCoreOpenResponsePacket` 的 `upgradeTargets` 为客户端提供目标等级、条件、解锁容量、`durationTicks` 和材料展示字段。

响应中的 `UpgradeProgress` 包含：

```text
targetLevel
startedAt
durationTicks
```

没有进行中的任务时发送 `UpgradeProgress.NONE`。

## 城市核心界面

- 普通等级卡片显示资金、人口、升级耗时、升级后区块/飞地容量和材料逐项状态。
- 材料满足度的汇总进度条不会显示。
- 只有服务器确认任务开始后，才显示 `UpgradeProgressBar` 升级计时进度条。
- 进度条在 `ProgressBar.screenTick()` 中按同步世界时间刷新百分比和剩余时间。
- 进度达到 100% 时，客户端只发送一次城市核心刷新请求；最终等级仍以服务端完成任务的结果为准。
- UI 使用 ORE 主题和既有伪下拉等级卡片，不直接访问 SQLite 或修改城市数据。

## 扩展要求

新增或修改等级时优先修改数据包，不要为特定等级增加 Java 分支。变更升级网络字段时，必须同步更新 `CityCoreOpenResponsePacket` 的编解码、`CityNetworkViewFactory` 的快照构造、`CityUpgradePanelFactory` 的显示，以及 `CityLevelDefinitionLoaderTest`。
